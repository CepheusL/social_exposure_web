# CLAUDE.md — project rules for AI assistants

Static marketing/data-explorer site for two papers (Unpacking Social Exposure
with pages at the repo root; Firm-Level Climate Change Exposure under
`/climate/`), behind a neutral project hub at `index.html`, served live by
GitHub Pages from `main` at https://sustainexposure.com/. See `README.md` for
the full structure and workflow.

## Hard constraints

1. **No build step.** Plain HTML/CSS/vanilla JS with a vendored Chart.js
   (`lib/chart.umd.min.js`). Do not introduce bundlers, npm dependencies, or
   frameworks.
2. **Push to `main` = immediate production deploy.** Substantive changes go
   through a branch + pull request; never force-push `main`; never delete or
   move the root `CNAME`.
3. **Never hand-edit `data/*.json` or `downloads/*` to change numbers.** They
   are generated by an external pipeline. If a figure looks wrong, flag it and
   fix it at the source.
4. **Two sub-sites share assets.** `css/style.css`, `js/app.js`, `js/charts.js`
   and `lib/` are shared; page logic is per sub-site (`js/<page>.js` vs
   `js/climate/<page>.js`). Pages under `climate/` use `../` relative paths.
   A change to shared files affects both sub-sites — check both.

## Working rules

- **Local preview:** `python3 -m http.server 8000` from the repo root; test
  `http://localhost:8000` and `http://localhost:8000/climate/`. Opening HTML
  via `file://` breaks data fetching.
- **Cache busting:** shared CSS/JS is loaded with `?v=N` (see current value in
  any page's `<link>`/`<script>` tags). Bump the number in **all pages of both
  sub-sites** whenever `css/style.css` or shared JS changes.
- **Site chrome:** header/footer are injected by `js/app.js`; per-paper config
  (nav, citations) is selected via `<body data-section="...">` (`social`,
  `climate`, or `home` for the hub, which has no page nav). The hub at
  `index.html` lists all projects; each project's landing page is set by the
  `landing` field in the `SECTIONS` array in `js/app.js`. Add new projects as a
  subdirectory plus a `SECTIONS` entry.
- **Copy style:** short sentences, plain wording, no em dashes.
- **Accessibility:** preserve the existing skip link, `aria-*` attributes and
  `sr-only` labels when editing pages.
- **Commit messages:** imperative and specific, e.g. "Add ranking page to
  climate sub-site", matching the existing history.
- **Data updates:** when replacing generated data, keep `data/meta.json`
  (`data_version`, `build_date`, `build_id`), `data/downloads.json` and
  `downloads/ReadMe.txt` consistent with the new files (coverage, row counts,
  byte sizes, variables).
- After a deploy to `main`, verify:
  `gh api repos/CepheusL/social_exposure_web/pages/builds/latest --jq .status`
  and spot-check the live site.
