# social_exposure_web

Website and data repository for two papers on firm-level exposure measures built
from earnings conference calls. The live site is served by GitHub Pages at
**https://sustainexposure.com/**.

| Sub-site | Paper | Site path |
|---|---|---|
| Unpacking Social Exposure | Liu, Sautner, van Lent & Zhang (2026), SSRN WP 6770779 | `/` (root) |
| Firm-Level Climate Change Exposure | Sautner, van Lent, Vilkov & Zhang (2023), *Journal of Finance* 78(3), 1449–1498 | `/climate/` |

## How the site works

- Pure static site: HTML, one stylesheet, vanilla JS. **No build step** — what is
  pushed is what is served.
- GitHub Pages serves the `main` branch root. **Every push to `main` redeploys
  the live site automatically.**
- The root `index.html` is a neutral hub ("Firm-level Sustainability Exposure")
  listing every hosted project. Each project's landing page is registered in the
  `SECTIONS` array in `js/app.js` (`landing` field: social → `overview.html`,
  climate → `climate/index.html`). New projects get a subdirectory plus an entry
  there.
- `CNAME` at the repo root points Pages at `sustainexposure.com`. Do not delete
  or move it.
- Header and footer are injected at runtime by `js/app.js`. Which paper's chrome
  and citation load depends on `<body data-section="...">` (`social` by default,
  `climate` under `/climate/`, `home` on the hub). The top-left brand is the
  site logo (`favicon-hub.svg`): it links back to the hub from every page. Each
  section also carries its own color palette via CSS variable overrides in
  `css/style.css`: orange (social, the default tokens), green
  (`[data-section="climate"]`), slate blue (`[data-section="home"]`). The hub's
  project cards pin their project's palette so they keep the orange/green
  identity.
- Charts use the vendored `lib/chart.umd.min.js` (Chart.js UMD). No CDN, no npm.
- CSS/JS changes are cache-busted with a `?v=N` query on `<link>`/`<script>` tags
  (currently `v=17`). **When you edit `css/style.css` or shared JS, bump the
  version in every page of both sub-sites.**

```

  meta.json                                Dataset version, coverage, build id
  downloads.json                           Manifest of download files (bytes, rows, columns)
  agg/, agg_q/                             Aggregates by country / industry / global
  firm/, firm_q/                           Firm-level series, chunked (index.json maps firm → chunk)

```

## Local preview

Run a local web server from the repo root (opening `index.html` via `file://`
will not work: pages fetch JSON data, which browsers block on the `file://`
protocol):

```bash
cd social_exposure_web
python3 -m http.server 8000
# then open http://localhost:8000 (social) and http://localhost:8000/climate/
```

## Data conventions

- `data/*.json` and `downloads/*` are **generated by the data pipeline, which
  lives outside this repo**. Never hand-edit them to "fix" a number; regenerate
  from the source instead.
- `data/meta.json` carries `data_version`, `build_date` and `build_id` — the
  January 2026 release covers 2003Q1–2025Q1 (15,369 firms, 92 countries).
  When the data are updated, keep `meta.json`, `downloads.json`, and
  `downloads/ReadMe.txt` consistent with the new files (coverage dates, row
  counts, byte sizes, variable list).
- The download zips contain CSVs with `gvkey`, `isin`, `cusip`, `ric` plus the
  exposure variables (`social_expo`, `emp_expo`, `dei_expo`, `stakeholder_expo`,
  `ethical_expo`, `crisis_expo`). Variable definitions live in
  `downloads/ReadMe.txt`.

## Collaboration workflow

**Pushes to `main` go live immediately.** There is no branch protection and no
CI gate, so:

- **Substantive changes** (JS behavior, layout, structure, data updates): work
  on a descriptive branch (`git switch -c fix-firm-search`), open a pull
  request, review, then merge. Check the deployed site after merging.
- **Small fixes** (typos, copy tweaks): a direct push to `main` is acceptable.
- **Never force-push `main`.**
- After deploying, verify the Pages build:
  `gh api repos/CepheusL/social_exposure_web/pages/builds/latest --jq .status`
  then spot-check https://sustainexposure.com/ (hard-refresh; the `?v=N`
  cache-bust only covers CSS/JS).

Commit messages: imperative and specific, matching the existing history, e.g.
"Add Climate Change Exposure section", "Rewrite site copy for clarity: shorter
sentences, plain wording, no em dashes".

## Site copy style

Established in the existing history: short sentences, plain wording, **no em
dashes**. Accessibility patterns (skip link, `aria-*` attributes, `sr-only`
labels) are already in place — keep them when editing pages.
